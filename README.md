# 교실 도구 허브 사용과 개발

## 그림과 화면 디자인

허브 개요 화면은 제목 최대 30px, 그림을 왼쪽에 둔 소형 카드로 조정했다. 네 도구 기준 PC 1024×768·1280×720·1366×720·1440×900·1920×1080에서 하단까지 스크롤 없이 표시한다. 모바일·큰 글자 확대·더 작은 창에서는 내용을 숨기지 않고 필요한 만큼 스크롤하며 44px 실행 버튼을 유지한다. 도구 내부 실행 화면의 크기는 별도로 유지한다.

크림·코코아·주황 디자인에 문구점 느낌의 대표 일러스트 네 장을 적용했다. PC는 2열, 760px 이하에서는 1열이며 카드 전체를 눌러 도구를 연다. 그림과 태그 배경은 타이머 살구·PDF 청록·수학 연두·일기 연보라로 구분한다. 버튼은 설명 문구와 직접 작성한 선형 아이콘을 함께 표시한다. 시스템 한글 글꼴·기존 노트 로고를 유지하며 키보드 포커스와 움직임 줄이기를 지원한다.

이미지는 `dist/assets/illustrations/`의 로컬 WebP 네 장(합계 약 178KiB)이다. 생성 방식·최종 프롬프트·각 경로는 ASSETS.md에, 변경 사유·예외·검증 결과는 DESIGN-AUDIT.md에 기록했다. 허브 아래쪽 이미지는 지연 로딩하며 그림 로드 실패 시에도 도구 이름과 실행 링크를 유지한다. 새 npm 의존성·외부 이미지 URL·글꼴 CDN은 추가하지 않았다. 다항식 게임 선택 화면에도 숲 그림을 재사용한다.

디자인 검증은 `node tests/design-browser-check.mjs '<Playwright index.mjs 경로>'`로 실행한다. 실제 일기 폴더를 사용하지 않고 임시 앱을 만들어 검사·종료·정리한다. `RUN_REGRESSION=1`이면 기존 허브·타이머 검사도 이어서 실행하고 `BROWSER_CHANNEL=msedge`로 Edge를 검사한다. 이미지 생성 원본은 앱의 배포 파일에 포함하지 않는다.

## Firebase 일기장 · 2026-10-12

[배포된 일기장](https://classroom-diary-098bae6e.web.app/#/diary)에서 **Google로 로그인**을 선택한 뒤 일기장 암호화 비밀번호를 만들거나 입력합니다. 로그인 계정마다 일기가 분리되고, 같은 Google 계정과 일기장 비밀번호를 사용하면 다른 기기에서도 암호화 기록을 읽습니다. 새로고침·브라우저 재실행 시 다시 로그인합니다. 일기장 비밀번호를 잊으면 기록 내용을 복구할 수 없습니다.

현재 배포는 Firebase 프로젝트 `classroom-diary-098bae6e`, Firestore Standard Native `(default)` / 서울 `asia-northeast3`, Firebase Auth Google 제공자, Firebase Hosting으로 구성됩니다. 클라우드 일기는 암호화되어 Firestore에 저장됩니다. 이름·이메일은 앱의 일기 데이터베이스에 복사하지 않으며 관리자 시크릿을 웹앱에 포함하지 않습니다. Google Auth 자체는 계정 인증용 프로필을 관리합니다. 기존 `data/diary/` 로컬 파일은 유지하며 클라우드로 자동 이관하거나 동기화하지 않습니다. 따라서 처음 Google 로그인하면 별도의 빈 일기장을 만듭니다.

기존 로컬 실행과 아래의 일기 제외 공개 빌드는 그대로 사용할 수 있습니다. Firebase에는 별도 `build/firebase` 산출물만 배포합니다. 소스 변경 후 개발 의존성을 `npm ci`로 설치하고 `npm run build:firebase`를 실행합니다. 고정 버전과 npm override를 검토한 뒤 변경하며 `npm audit`를 확인하세요. 공식 CLI로 배포합니다.

```powershell
npx -y firebase-tools@latest deploy --only 'firestore:rules,firestore:indexes,hosting' --project classroom-diary-098bae6e
```

Google 제공자는 이미 활성화되었습니다. 새 환경에서 제공자를 다시 설정해야 한다면 공식 CLI로 로그인하고 `npm_config_cache`를 검증된 CLI 캐시로 지정한 뒤 `node scripts/configure-firebase-auth.mjs`를 실행합니다. 이 도구는 현재 계정의 OAuth 지원 연락처를 실행 중 읽고 임시 운영 설정을 사용한 뒤 제거합니다. 연락처·계정 토큰을 소스나 배포 파일에 넣지 않습니다.

검증은 기존 단위 테스트와 `tests/firebase-rules-check.mjs`, `tests/firebase-flow-check.mjs`, `tests/firebase-browser-check.mjs`, `tests/firebase-oauth-check.mjs`를 사용합니다. 규칙·저장 흐름 검사는 Java 21과 `firebase-emulators.json`을 사용해 `demo-classroom-diary` 에뮬레이터에서만 수행합니다. 실제 사용자 기록이나 운영 인증 토큰을 테스트 자료로 사용하지 않습니다. 자세한 변경 사유·부작용·예외·공급망·검증 한계는 [FIREBASE-AUDIT.md](FIREBASE-AUDIT.md)를 참고하세요.

## 로컬에서 실행하기

Windows에서 `start.cmd`를 더블클릭하고 브라우저로 `http://127.0.0.1:4173`에 접속합니다. 실행 창을 열어두고 사용하며, 종료할 때 창에서 Ctrl+C를 누릅니다. 이 실행 주소는 현재 PC에서만 접근할 수 있습니다.

Node.js 24.12.0 이상이 설치되어 있으면 다음 명령으로도 실행할 수 있습니다. 로컬 사용에는 패키지 설치나 빌드가 필요하지 않습니다. `start.cmd`는 PATH의 Node.js를 우선하고, 없으면 Codex에 이미 설치된 런타임을 찾습니다. 공개 배포본은 아래의 별도 빌드 명령으로 만듭니다.

```powershell
cd classroom-hub
node scripts/serve.mjs
```

4173 포트가 다른 프로그램에서 사용 중이라면 다음처럼 바꿉니다.

```powershell
$env:PORT = '4174'
node scripts/serve.mjs
```

HTML 파일을 직접 더블클릭하면 브라우저의 모듈 보안 제한으로 작동하지 않을 수 있으므로 로컬 서버를 사용합니다. 이 서버는 개발용이며 인터넷 배포 서버로 사용하지 않습니다.

## 수업에서 사용하기

1. 도구함의 교실 타이머 카드를 선택합니다.
2. 1·3·5·10분을 선택하거나 분·초를 입력합니다. 1초부터 99분 59초까지 사용할 수 있습니다.
3. 시작하기를 누르고 필요하면 전체화면으로 확대합니다.
4. 일시정지·계속하기·초기화를 사용합니다. 종료 시 화면 안내와 선택된 소리가 나옵니다.

소리를 끌 수 있고, 전체화면을 사용할 수 없으면 화면 내 확대가 적용됩니다. 도구함 복귀 시 일시정지되며 돌아와 계속할 수 있습니다. 새로고침·탭 종료 시 설정은 초기화됩니다. 모바일 잠금·절전·숨겨진 탭에서는 알림이 늦어질 수 있으므로 수업 중에는 화면을 켜둡니다. 각 기기는 독립적으로 작동합니다.

## PDF 글자 수·교정 후보 검사

도구함에서 **PDF 검사**를 선택하거나 `http://127.0.0.1:4173/#/pdf`로 접속합니다. PDF 한 개를 선택하거나 끌어놓으면 전체·쪽별 글자 수와 흔한 한글 오타·띄어쓰기 교정 후보를 표시합니다. 결과는 **엑셀 다운로드**로 `.xlsx` 파일을 받습니다. 검사 요약과 교정 후보 두 시트가 포함됩니다.

텍스트가 없는 쪽은 한글·영문 OCR로 읽습니다. 글과 사진이 섞인 쪽은 **모든 쪽을 OCR로 읽기**를 선택하세요. 흐린 사진·표·여러 단·손글씨에서는 누락이나 오인식이 생기므로 쪽별 추출 내용과 원문을 비교해야 합니다. 교정 후보는 등록된 규칙만 검사하며 정밀 문맥·문법 검사가 아닙니다. 후보가 없다고 오류가 없는 것은 아닙니다.

공백 포함 글자 수는 줄바꿈을 제외하고 문장부호를 포함합니다. 공백 제외는 공백·탭·줄바꿈을 제외합니다. 한글 조합 문자와 이모지는 보이는 문자 단위로 세며 머리말·꼬리말도 포함합니다. OCR 결과에 따라 수치가 달라질 수 있습니다. 제한은 **25MB, 100쪽, 추출 텍스트 200만 코드 단위, 교정 후보 1만 개, 처리 10분**입니다. 암호가 필요한 PDF는 지원하지 않습니다. 오류 시 불완전한 결과를 내보내지 않습니다.

PDF와 결과는 현재 브라우저 메모리에서만 처리합니다. 업로드·분석 API·브라우저 영구 저장을 사용하지 않으며 지우기·도구함 이동·새로고침으로 상태를 폐기합니다. OCR 엔진과 언어 모델도 앱의 정적 파일에 포함되어 CDN 접속이 없습니다. 메모리의 보안 삭제를 보장하는 기능은 아닙니다. 선택한 파일명과 전체 원문은 엑셀에 넣지 않습니다. **주변 문맥 포함**은 기본으로 꺼져 있으며, 켜면 원문의 일부와 개인정보가 내려받은 파일에 포함될 수 있습니다. 사용자가 저장한 엑셀 파일은 자동 암호화되지 않습니다.

처음 OCR을 실행하면 포함된 엔진·모델 약 20MB를 읽으므로 일반 텍스트 PDF보다 느립니다. 스마트폰에서는 큰 스캔 문서를 여러 작은 PDF로 나누면 부담을 줄일 수 있습니다. 인터넷 주소로 공개하더라도 문서는 브라우저 안에서 처리되지만 정적 호스팅의 일반 접속 기록은 별도로 확인해야 합니다.

## 다항식 숲 탐험

허브의 **다항식 숲 탐험** 카드 또는 `http://127.0.0.1:4173/#/polynomial`에서 실행합니다. 다람쥐·거북이의 이동·점프 능력은 같습니다. 고1 공통수학1 다항식의 연산, 항등식·나머지정리·인수정리, 인수분해를 세 길로 나누고 각 길에 직접 작성한 4지선다 6문제(총 18문제)와 해설을 제공합니다. 문제·정답을 수정하려면 `dist/polynomial-data.mjs`를 편집합니다.

PC에서는 게임 화면을 선택하고 방향키 또는 A/D로 이동, 스페이스·위쪽 방향키·W로 점프, P로 일시정지합니다. 모바일에서는 좌우·점프 버튼을 사용합니다. 물음표에서 문제를 풀 때는 게임이 멈춥니다. 정답 +100점, 도토리 +10점, 나무 충돌 −20점이며 0점 미만으로 내려가지 않습니다. 충돌 시 직전 문제 뒤로 돌아가고 이미 푼 문제나 모은 도토리로 중복 점수를 받지 않습니다. 자동 이동·퀴즈 집중 모드도 제공합니다.

뱃지는 세 길의 완주, 한 길의 6문제 전부 정답, 직접 이동 모드에서 무충돌 완주, 두 캐릭터로 각각 완주로 얻는 총 6종입니다. 모든 길을 처음부터 선택할 수 있습니다. 완료 화면에 정답 수·점수와 전체 문제의 내 답·정답·해설을 표시합니다. 최고점·뱃지·완주 캐릭터만 현재 브라우저에 저장하며 이름·학교·학번·개별 응답은 영구 저장하지 않습니다. 자동 이동 모드에서도 학습 뱃지는 얻지만 점프 뱃지는 얻지 않습니다.

저장 차단 시 화면에 안내하고 메모리에서 계속 사용합니다. 새로고침·선택 화면 이동은 진행 중 탐험을 종료하며 완주 기록만 유지합니다. 다른 탭·창으로 이동하면 자동 일시정지하고 복귀 후 계속하기를 눌러야 합니다. ‘이 게임 기록 지우기’는 두 번 확인해서 이 게임의 기록만 삭제합니다. 저장 기록은 기기 간 동기화되지 않으며 브라우저 설정 변경으로 사라질 수 있습니다. 점수는 개인 복습용이고 성적 평가·부정행위 방지 기능은 없습니다.

신규 외부 라이브러리나 온라인 이미지·글꼴·분석 서비스 없이 캔버스 그림과 기존 허브 디자인을 사용합니다. 허브 연결은 기존 로컬 프로젝트 안에서 완료했으며 인터넷 배포는 포함하지 않습니다.

## 오늘의 일기 · 로컬 폴더 데이터베이스

허브의 **오늘의 일기** 카드 또는 `http://127.0.0.1:4173/#/diary`에서 엽니다. 기존 서버가 실행 중이면 종료하고 다시 실행해야 새 저장 API를 사용할 수 있습니다. 4173 포트가 사용 중이라면 위 안내대로 PORT를 4174로 설정하세요.

`start-diary.cmd`를 더블클릭하면 4174 포트로 실행합니다. 이 경우 주소는 `http://127.0.0.1:4174/#/diary`입니다. 같은 데이터 폴더를 사용하는 서버가 이미 열려 있으면 포트가 달라도 두 번째 실행을 거부합니다. 기존 서버 주소를 사용하거나 기존 서버를 Ctrl+C로 종료한 뒤 다시 실행하세요.

첫 사용 시 12자 이상의 비밀번호를 두 번 입력하여 일기장을 만듭니다. 날짜별로 한 편씩 제목·내용·기분을 작성하고 **일기 저장**을 누릅니다. 목록에서 일기를 열어 수정·삭제하며 제목·내용·날짜로 검색합니다. 내용은 최대 20,000자, 제목은 120자입니다. 새 일기의 날짜에 이미 기록이 있으면 기존 일기를 목록에서 열어야 합니다. 저장 전 화면 이동에는 확인이 표시되고, 저장 중에는 이동이 제한됩니다. 비밀번호는 기본적인 길이만 검증하므로 다른 서비스와 겹치지 않는 긴 비밀번호를 사용하세요.

데이터베이스는 `classroom-hub/data/diary/vault.json`에 저장하는 **암호화된 JSON 파일**입니다. 브라우저 저장소와 클라우드 데이터베이스를 사용하지 않습니다. 파일은 최초 일기장 생성 시 만들어지며 날짜·제목·기분·내용 모두 AES-256-GCM으로 암호화합니다. 키는 비밀번호와 무작위 salt로 PBKDF2-SHA-256 600,000회 연산하여 브라우저 메모리에서 파생하며 비밀번호와 키를 디스크에 저장하지 않습니다. 전체 암호화 파일은 8MiB 이하, 일기는 10,000편 이하로 제한합니다. 제한을 넘으면 기존 파일을 보존하고 저장 실패를 안내합니다.

비밀번호를 잊으면 복구할 수 없습니다. 백업하려면 서버를 종료한 뒤 `data/diary/` 폴더를 별도 안전한 폴더에 복사하세요. 복원도 서버를 종료한 뒤 같은 위치에 넣고 기존 비밀번호로 여세요. 암호화된 백업 파일에도 비밀번호가 필요합니다. 삭제한 기록은 현재 파일에서 제거되며 직접 만든 과거 백업에는 남을 수 있습니다. 자동 백업·비밀번호 변경·계정별 분리는 제공하지 않습니다.

일기장을 잠그거나 화면을 떠나면 앱의 키·기록 참조와 편집 화면을 제거합니다. 열린 동안에는 브라우저 메모리와 화면에서 평문을 사용하며 메모리의 보안 삭제를 보장하지 않습니다. 잠금은 저장 파일의 변경 권한을 제어하는 로그인 기능이 아닙니다. 이 PC의 동일 사용자 권한을 가진 프로그램은 파일을 삭제하거나 암호화 파일을 바꿀 수 있으므로 OS 계정과 폴더 권한으로 보호해야 합니다.

서버는 `127.0.0.1`에만 열리고 정확한 Host·동일 출처·전용 요청 헤더를 검사합니다. CORS 허용 헤더를 보내지 않으며 데이터 폴더는 정적 서비스 범위 밖에 두고 Git에서 제외합니다. 임시 파일에 쓰기·동기화한 뒤 원본을 교체합니다. 서버 실행 잠금과 저장 작업 잠금은 파일의 배타적 생성으로 프로세스 간 충돌을 차단합니다. revision이 바뀌었거나 다른 저장 작업이 진행 중이면 덮어쓰지 않습니다. 공개 정적 빌드에는 일기 기능을 포함하지 않습니다.

강제 종료·정전 뒤에는 `data/diary/.server.lock` 또는 `.write.lock`이 남아 실행·저장이 거부될 수 있습니다. 오래됐다는 이유만으로 자동 삭제하지 않습니다. 해당 프로젝트를 사용하는 모든 서버가 종료됐음을 확인하고 `data/diary/`를 안전하게 백업한 뒤, 남아 있는 잠금 파일만 수동으로 제거하세요. `vault.json`은 삭제하지 않습니다. 서버가 동작 중인지 확실하지 않으면 제거하지 마세요. 운영체제 ACL 변경은 수행하지 않으며 같은 OS 계정의 악성 프로그램에 대한 파일 보호는 보장하지 않습니다.

일기 검색·제목·본문에는 브라우저 맞춤법 검사와 자동완성 차단 속성을 적용했습니다. 브라우저 확장 프로그램·번역·OS 입력기의 별도 처리는 앱이 통제하지 못합니다.

일기 기능이 있는 로컬 실행의 HTML과 서버는 CSP `connect-src 'self'`를 사용하며 외부 출처 연결을 차단합니다. 일기를 제외한 공개 빌드는 `connect-src 'none'`입니다. 이전 PDF 개발 기록의 정책은 당시 버전의 설명이며 현재 배포에는 아래 공개 빌드 지침을 적용합니다. 신규 외부 라이브러리는 도입하지 않았습니다.

검증: `node --test tests/*.test.mjs`, 브라우저 검증은 `node tests/diary-browser-check.mjs '<기존 Playwright index.mjs 절대 경로>'`로 실행합니다. 브라우저 검증은 임시 복제 폴더·4186 포트·합성 기록을 사용하므로 실제 일기 파일을 건드리지 않습니다.

## 새 도구 등록

`dist/tools.mjs`에 고유 ID·이름·설명·경로를 추가하고 `dist/app.mjs`의 `routes`에 해당 화면의 렌더 함수를 등록합니다. 등록된 내부 경로만 카드로 표시되며, 화면 함수를 등록하지 않은 카드나 중복 ID·경로는 제외됩니다.

```javascript
// tools.mjs의 tools 배열에 추가하는 합성 예시
{ id: 'example-tool', title: '예시 도구', description: '새 도구의 설명',
  route: '#/example', category: '수업 도구' }

// app.mjs의 routes 목록에, 해당 화면 함수를 import한 후 추가
['#/example', () => renderExample(main)]
```

화면은 떠날 때 타이머·작업·이벤트를 정리하는 함수를 반환할 수 있습니다. `hub-view.mjs`에서 도구별 장식을 구분합니다. 새 도구가 학생 정보·로그인·외부 API를 사용한다면 해당 기능의 보안·권한 설계를 별도로 진행합니다.

## 테스트

```powershell
node --test tests/*.test.mjs
```

브라우저 점검은 기존 Playwright와 Chrome이 설치된 환경에서만 실행합니다. 앱 구동에는 이 도구들이 필요하지 않으며 신규 패키지를 자동 설치하지 않습니다. 로컬 서버를 실행한 상태에서 기존 Playwright의 `index.mjs` 절대 경로를 전달합니다.

```powershell
node tests/browser-check.mjs '<기존 Playwright의 index.mjs 절대 경로>'
```

Edge를 검사하려면 `$env:BROWSER_CHANNEL = 'msedge'`를 먼저 설정합니다. 허브·타이머 브라우저 점검은 기본 포트 4173 또는 환경 변수 PORT를 사용합니다. 공개 미리보기를 검사할 때는 `$env:PREVIEW_STATIC = '1'`을 지정합니다. 화면 이미지는 `qa` 폴더에 생성되며 버전 관리에서 제외됩니다. 자세한 결과와 미검증 환경은 `AUDIT.md`에 기록합니다.

PDF 통합 검사는 `node tests/pdf-browser-check.mjs '<Playwright index.mjs 경로>' '<선택: openpyxl·pypdf 설치된 Python 경로>'`로 실행합니다. 개인 정보가 없는 합성 PDF를 메모리에서 생성하며 스캔 OCR·다운로드·취소·암호·자원 제한·외부 요청과 저장소 사용을 검사합니다. Edge 자체 다운로드 패널의 `edge:` 요청은 외부 통신과 구분합니다. 앱 실행에 Python·Playwright는 필요하지 않습니다.

## 인터넷 주소로 배포하기

배포 대상은 **`build/static` 폴더**입니다. `dist`는 일기를 포함한 로컬 개발 소스이므로 공개 배포하지 않습니다. 공개 빌드는 타이머·PDF·다항식 게임만 포함하며 일기 카드·경로·암호화 파일·CSS·저장 API를 제외합니다. `.openai/hosting.json`의 정적 디렉터리도 `build/static`을 가리킵니다. 서비스 등록·배포·외부 전송은 수행하지 않습니다.

```powershell
node scripts/build-static.mjs
node scripts/preview-static.mjs
```

첫 명령은 설치·다운로드 없이 고정된 vendor 해시를 검사하고 공개 파일을 생성합니다. 알 수 없는 입력 파일·심볼릭 링크·수정된 기존 빌드가 있으면 자동 삭제하지 않고 실패합니다. 새 도구를 추가할 때는 `scripts/build-static.mjs`의 공개 파일 허용 목록도 검토합니다. 두 번째 명령은 생성된 공개 파일만 loopback에서 제공하며 일기 데이터 폴더나 잠금 파일을 만들지 않습니다. npm 사용 시 `npm run build`, `npm run preview`도 같습니다.

빌드는 `build/.build.lock`으로 중복 실행을 거부하며 기존 공개본을 임시 보관한 뒤 새 공개본으로 교체합니다. 강제 종료 뒤 잠금이나 `.previous-*` 폴더가 남았다면 모든 빌드가 종료됐음을 확인하고 기존 파일과 릴리스 기록을 보존한 뒤 복구하세요. 남은 잠금을 자동으로 제거하거나 알 수 없는 파일을 덮어쓰지 않습니다.

`build/security-headers.json`에는 호스팅에 적용할 기본 헤더와 `/ocr-worker.js` 전체 대체 헤더, JavaScript MIME 요구사항이 들어 있습니다. **호스팅이 이 JSON을 자동 적용한다고 가정하지 않습니다.** 선택한 호스팅의 실제 헤더 설정으로 옮기고 HTTPS 응답을 검사해야 합니다. OCR 경로에는 기본 CSP와 별도 CSP를 중복 추가하지 말고 해당 경로용 CSP로 교체하세요. 기본 정책에 남은 Wasm 차단이 함께 적용되면 OCR이 작동하지 않습니다. 헤더 설정을 지원하지 않거나 실제 검증에 실패하면 배포를 보류합니다.

공개 화면·OCR worker 모두 `connect-src 'none'`이며, 로컬 일기 실행만 `'self'`를 사용합니다. 일반 화면은 `script-src 'self'`, `/ocr-worker.js`만 `script-src 'self' 'wasm-unsafe-eval'`입니다. 이는 OCR WebAssembly 컴파일용이며 일반 JavaScript eval은 허용하지 않습니다. `frame-ancestors 'none'`과 `X-Frame-Options: DENY`는 응답 헤더로 적용합니다. `.mjs`·`.js`는 JavaScript MIME으로 제공해야 합니다. 학교망·접속 로그 보관·실제 기기를 별도로 검증합니다.

`build/static/BUILD-MANIFEST.json`은 파일별 SHA-256과 릴리스 ID를 기록합니다. 같은 배포본은 `build/releases/<릴리스 ID>/`에 보관되어 롤백에 사용할 수 있습니다. 빌드 폴더는 Git에서 제외하므로 운영자가 별도 안전한 저장소에 보관해야 합니다. 이 기록은 소스 Git 이력을 대체하지 않습니다. 배포 전 소스 기준 커밋도 필요하며 이 작업은 Git 쓰기 권한을 변경하지 않습니다.

의존성 버전·라이선스는 `THIRD_PARTY.md`, 로컬 고정 해시는 `scripts/vendor-checksums.json`에 있습니다. `node scripts/verify-vendor.mjs`는 파일 변조만 검사합니다. 최신 보안 권고·내장 전이 의존성·Node 취약점은 외부 조회 승인이 없어 미확인입니다. 실제 공개 전에는 해당 검토를 별도로 완료해야 합니다.
